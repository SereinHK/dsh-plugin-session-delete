A predicted path can no longer be the only path.

- DSH **0.2.2-rc.3** derives a Session's project directory from the path it *resolved*, and on
  Windows that carries the on-disk casing — so a header saying `…\Downloads\mac` can sit in a
  directory named `--…-Downloads-Mac--`. The plugin's `projectKey` is a pure function over the
  header and cannot reproduce that; the runtime-contract check caught it here on 1 of 17
  Sessions.
- Deletion and restore were already safe — they scan the root when the prediction misses. The
  **size measurement** had no fallback, so such a Session reported no size. Every read now
  treats the prediction as a fast path with a scan behind it.
- `verify-runtime-contract.mjs` now separates the assumptions the plugin **depends** on from
  the one it merely **predicts**: the run reports `7/7 assumptions still hold` plus a named
  prediction-drift line, rather than calling the whole plugin untrustworthy over a path it
  already knew how to find another way.

**Verified:** 31 package tests, 100 host-route checks against the built bytes (including a
Session whose project directory differs only in casing), 69 render and interaction checks.

**Install**

```sh
dsh plugin --profile <profile> add https://github.com/SereinHK/dsh-plugin-session-delete.git
```
