The destructive confirmation reads as a warning, not as a button.

- The question used to sit **in the button label**, with the danger expressed by the
  button's fill. Now the warning is a line of **red text in the dialog body**, naming what
  will go — including the conversation's own title — and the button is a two-word label:
  **确定删除** / **确定清空**, filled red once the confirmation is showing.
- Both take the theme's `--dsw-alias-state-error-primary` token, so they follow it in light
  and dark, and `Button`'s lack of a danger variant is worked around with the same token the
  menu row's `danger` uses rather than a literal.
- Pinned by checks that assert the shape rather than the pixels: the confirm control's label
  is exactly "确定删除" and not the sentence, the warning carries the danger colour, and the
  row's own action is red before it is filled.
