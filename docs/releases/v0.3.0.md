Stored Sessions that fell under "ungrouped" are put back where they belong.

**Added**

- `POST /api/session.adopt`, plus the same repair once at plugin startup. A workspace
  owns Sessions through an ownership account, and the runtime attaches a Session only as
  it is *created* — so when a folder is added as a workspace, or renamed and added again,
  its older Sessions keep rendering under "ungrouped" and nothing in the UI can fix them.
  This attaches every stored Session whose header path resolves to a registered workspace.

**Deliberately not done**

- Nothing is created, moved or deleted. An already-attached Session is skipped before the
  call (the method is idempotent anyway), a folder that no longer exists is skipped, and a
  Session whose header disagrees with the workspace path is left for the operator instead
  of being papered over.

**Verified:** 31 package tests, 95 host-route checks against the built bytes (adoption
among them: the mount repair, idempotence on a second run, a vanished folder, a folder
that is not a workspace, a Session with no cwd), 64 render and interaction checks.

**Install**

```sh
dsh plugin --profile <profile> add https://github.com/SereinHK/dsh-plugin-session-delete.git
```
