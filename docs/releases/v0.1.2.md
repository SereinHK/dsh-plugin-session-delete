The blank-Session cleanup works, by asking the Host instead of guessing.

Two earlier attempts decided blankness in the page, and both were wrong for the same
reason: for a Session that is not resident, the page has no durable answer. A list row's
`blank` describes a live Session's first turn, and a row's projection block is loaded only
for the Session being viewed — so a cleanup run over a workspace full of empty
conversations reported "nothing to clean".

**Added**

- `POST /api/session.unused` — reports the durable per-Session facts from the same
  projection cache the Session list itself uses: whether the stored log holds an accepted
  prompt, when the last one was, and whether the cache could answer at all.

**Changed**

- The cleanup applies its policy (one-hour grace window, live Session, open Session) to
  those Host facts rather than to a display row, and loads them when the dialog opens.
- An unprovable Session is never deleted; the dialog says how many it skipped instead of
  implying the workspace is clean.
- A Host failure is worded as a failure, never as an empty result.

**Verified:** 26 package tests, 59 host-route checks against the built bytes (proven,
unproven, cache-failure and body-validation cases among them), 47 render and interaction
checks — plus a run in a real browser on a workspace holding five empty conversations,
where four were listed and the ten-minute-old one was held back by the grace window.

**Install**

```sh
dsh plugin --profile <profile> add https://github.com/SereinHK/dsh-plugin-session-delete.git
```
