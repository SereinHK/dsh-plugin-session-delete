A conversation can be deleted after switching away from it — no restart needed.

**Fixed**

- Deleting refused with `session-live` whenever the Session was **resident** in the process.
  `ctx.sessions.get` keeps answering yes for as long as DSH runs, and switching to another
  conversation does not release it — so the instruction in that message ("switch to another
  conversation and delete it then") could not be followed, and the only way through was to
  restart the application.
- Residency is no longer a refusal. The move is attempted and the filesystem decides: a log a
  running turn still holds open fails to rename, and **that** is `session-open`, worded for
  what it is with the fix that applies — wait for the turn to finish, or restart.
- A failed move no longer swallows its reason. A held path and a broken one need different
  words and only one of them is worth retrying, so `moveToTrash` returns the error and the
  route reports it. `isLockedError` (`EBUSY`, `EPERM`, `EACCES`) is the whole classification.

**Verified:** 31 package tests, 99 host-route checks against the built bytes (a resident
Session being moved rather than refused, the trash landing where it should, the removal
event, the classifier, and a non-lock failure keeping its real reason), 69 render and
interaction checks.

**Install**

```sh
dsh plugin --profile <profile> add https://github.com/SereinHK/dsh-plugin-session-delete.git
```
